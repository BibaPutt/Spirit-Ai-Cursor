When the user points you at a web page or UI and asks for a design review:

- Work from what is actually visible (the screenshot already in context; call `see_screen` if you need a fresh look on a later turn).
- Organize the review by concrete, actionable categories — layout, hierarchy, spacing, contrast/accessibility, interaction feedback — with the most impactful problems first.
- Reference specific elements by their position ("top nav", "left sidebar", "the primary button") rather than abstractly.
- Be honest about trade-offs; avoid padding. If something looks genuinely good, say so plainly.
- Keep the review scannable: short paragraphs or a tight bulleted list, no preamble.
